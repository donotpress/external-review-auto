# Release notes: what each release found

Moved out of the README on 2026-10-16 so the README stays a usage guide. Newest first, unchanged from the README text.

See also the annotated git tags (`git tag -n99`) and GitHub releases, which carry the full body for each version.

- **A retraction: the review archive was never destroyed (v2.8.2)** — the `v2.8.1` release notes reported that a test I had written had deleted this repository's entire `.external-reviews/`, ~35 rounds, and named a mechanism. **All of it was wrong.** Another session had *moved* the archive to `%USERPROFILE%\.claude\era-archive\external-review-auto-selfreviews` for a measured start-up cost (~206 of 555 paths opened at session start were these files) and left a note in the repo root saying so. Everything is intact. The named mechanism was disproved three ways — `Join-Path $null 'x'` throws rather than returning a relative path; the suspect test re-run against a decoy left it untouched; the whole suite run against decoys deletes nothing. The guard, the 142 converted call sites and the backup tool built on that premise are **reverted**, and the measurement that declines them is recorded: every one of the suite's 142 recursive deletes targets the system temp directory, and runtime code contains none. Written up in `docs/assessments/2026-09-01-review-archive-false-alarm.md`, because a confident causal story published before it was checked is the exact failure the release it appeared in was documenting.

- **The sweep for surviving twins, and the panel that found four more inside it (v2.8)** — a pass over every `fix:` commit since v2.3 asking *is there a second implementation of the rule this fixed, and was it fixed too?* Then the 4-seat panel was pointed at the sweep itself, and found that two of its own fixes were wrong and two of its new tests could not fail. Both halves are below because the second half is the point: **the author's sweep found six twins; one round of review on that sweep found four more, two of them in the sweep's own code.**

  **What the sweep found.** (1) **The v2.7 `-BlindSeat` fallback fix is a no-op.** It threaded `-BundleOverrides` into the fallback re-dispatch; the map is keyed by preset, and `Resolve-EraAgyFallback -Exclude` guarantees the fallback's preset is absent from it, so the lookup could never hit and a blinded seat's replacement still read the sighted bundle. It shipped with a source-assertion test that the parameter *exists*. (2) **A third copy of "an ambiguous model hint must not be resolved silently."** The **opencode** branch of `Resolve-ModelFromHint` was first-match-wins over `_registry.json` file order — invisible to both previous sweeps because it is not a hashtable and therefore never varied run to run. Measured: `deepseek` matched two models and returned `deepseek-v4-`**`pro`**, at twice the input price of the `-flash` in the standard panel; `minimax` matched 8, `flash` 14. (3) **The run mutex reintroduced the defect the stall-clamp fix removed** — an adapter cannot grant itself time the dispatcher will not wait, and the opencode run lock waited a fixed **900s** against a 600s default budget, started the adapter's own `$deadline` *after* that wait, and retried `database is locked` with the budget unchanged. Observed live during the work: a seat spent 400s of its 1800s in the queue. (4) `Remove-EraBundleComments` read its bundle with `[System.IO.File]` and no `Resolve-Path` — the fail-open fixed in `Get-EraBundleLineCounts` eleven lines up the same file. (5) Two more fail-opens where a failed measurement was indistinguishable from a real one: the opencode adapter sized its bundle with `catch { 0 }` (0 reads as *small enough to attach*, i.e. silent 50 KiB truncation), and `backends/agy.ps1` with `else { 0 }` (zero estimated tokens **disarms the reviewer's cost cap**). (6) The per-reviewer cap is duplicated between plan and adapter with nothing checking the copies. Also: the v2.7 block-comment **closer** fix had shipped with no regression test; `backends/opencode.ps1` cited a parity test file that did not exist; and **which seat was blinded is now in the metadata**, with the blind bundle's SHA-256 — the arm label of the A/B lived only in a console line and in the prose of the assessment that scored it.

  **What the panel found in the sweep.** (a) **`Resolve-OpencodeRunBudget` reintroduced its own defect, twice.** The first cut floored the effective budget with `Max(60, remaining)` — for any budget under 60s that hands the adapter more time than it was given. The second cut capped that floor at `TimeoutSec`, and the **blinded seat** pointed out the case that matters was still wrong: at `elapsed >= TimeoutSec` the floor returns 60s, and *the test shipped with it asserted that 60*, so the suite was green while over budget. A floor cannot fix a spent budget. `EffectiveSec` is now exactly what remains and `Viable` says whether that is worth launching; an exhausted seat refuses instead of starting a run nobody will wait for. (b) **`Find-AgyModelFromHint` is a FOURTH copy of the hint rule, and the only one that never worked at all.** Its accumulator was named `$matches` — an automatic variable PowerShell overwrites on every `-match`, which is the loop's own condition — so the list became a hashtable holding the last match plus regex group 0, `.Count` counted keys, and the tier sort had one object to sort. Measured across five separate processes, `-AgyModel gemini` returned **three different models**. In-process repetition cannot see this, which is why three previous fixes to this rule did not. (c) **`max_bundle_tokens` on an opencode preset refused rounds the adapter would have delivered** — the plan applied the key to every backend while no opencode adapter reads a token ceiling. That channel is byte-bounded; the key is now ignored there with a NOTE, and still binds on `claude`, where the CLI itself rejects on tokens. (d) Four of the sweep's new tests could pass against a gutted subject, including one whose "stability" assertion was an identity for every possible implementation, and `blind_seat` could name two seats after a fallback. All four are now behavioural or removed. (e) **The citation checker had been calling correct citations fabricated.** It knew one coordinate system — the per-file line numbers a bundle prints — while a **read-tool** seat opens the bundle with its own Read tool, which reports **bundle-absolute** numbers. Measured across 62 archived seat-responses (25 rounds): **128 of 155 flagged citations (83%), out of 1,570 checked, land inside the named file's own span in the bundle** — real pointers, counted from the top of the wrong file. **The two frames OVERLAP and that half is invisible:** where a bundle coordinate is also a valid in-file line for the same file, nothing resolves it — at most 203 of those 1,570 citations (12.9%), and measurably ~40 (2.5%): the other 163 sit in responses that never use the bundle frame anywhere it is visible. So 83% is a rate over the *flagged* set, not over frame errors, and the prompt instruction below is the only thing that touches the half era cannot see. `runtimes/resolve-model.ps1:1780`, reported as invented, is in-file line 169: the exact `Sort-Object TierRank/SettingsValue` line its finding was about. era now reports the two frames separately and **translates** the bundle-absolute ones, checks each seat against the bundle it actually read (a blinded seat was being checked against the sighted one), and the read-tool prompt says which numbering to cite. The claim that one default-panel seat "invents four in ten of its citations" is **withdrawn**; `deepseek-flash` turns out to have fabricated nothing at all across eight arms. **And the project had already written this down**: `docs/assessments/2026-08-14-quote-grounding-declined.md` declined line-grounding as a metric, listed "reviewers do not share a citation convention… `backends/opencode.ps1:3021` is not a per-file line number in any tree; it is a position in the merged document" as confound 3, and closed *"a future proposal should be tested against the three confounds above before it is built"*. Eighteen days later v2.4 built one and did not. Confounds 1 and 2 — agentic filesystem access and `-Diff` subsets — are still unhandled and now say so.

  Also from the panel: the agy cost cap needs ~3.3M input tokens per attempt to fire, so the claim that it replaced dead code with a live gate was **withdrawn** — the parity is real, the liveness is not.

- **Two findings the audit round made and nobody acted on (v2.7.1)** — both real. First: the v2.4.1 fix that made model-hint resolution deterministic touched `resolve-model.ps1` and *only* there, while `era.ps1` carries a **second, independent implementation** of the same rule (the `-AgyModel` path) which kept the exact defect that release claimed to fix — a bare `.Keys` loop with no defined enumeration order, and a `Sort-Object` tie silently inheriting it. That is the same *one rule, two implementations, one of them fixed* shape the panel kept flagging, committed while fixing the previous instance of it. Second: `max_bundle_tokens` is honoured by the plan and read by **no adapter**, so raising it makes the plan say "fits" and the `claude` CLI answer `Prompt is too long` after the round is already paid for on every other seat — the asymmetry the opencode attach cap had, one backend over. Lowering a ceiling stays quiet; raising a **measured** one now warns, because the measurement is the thing that knows.

- **The first panel ever pointed at these releases found a critical (v2.7)** — six of eight releases had gone out on their author's review alone. One 4-seat round on that diff returned, all confirmed: `-PremiseCheck` was **discarded on every `-Diff` round** while its own log line said it had been appended (the section was written before `Merge-EraDiffPrompt`, whose `if (-not $ExistingCarriesCallerContent) { return $DiffPrompt }` threw it away); `-BlindSeat` still deleted code at the block-comment **closer** — the exact mirror of the opener bug fixed one release earlier, and the same shape found the same way; `-BundleOverrides` was never passed to the fallback re-dispatch, so a blinded seat's fallback silently got the sighted bundle; citation warnings were written **after** the metadata that was supposed to carry them; and a `bundle-access-refusal` — where the model never saw the bundle and *nothing was reviewed* — was categorised `answered-badly`, throwing away the branch the detector had just computed. Python triple-quote handling was **removed** rather than fixed: a line scanner cannot tell an opening docstring delimiter from a closing one, and its failure mode deletes code. Also closed: `Get-EraBundleLineCounts` failed **open and silently** on any read error (`Test-Path` is PowerShell-aware, `[System.IO.File]` resolves against the process CWD), and four tests that would have passed against a gutted implementation — including one asserting `-BeLike '**/*'`, which matches every non-empty string.

- **One seat can review the code without the narrative (v2.6)** — `-BlindSeat <preset>` hands a single reviewer the bundle with comments blanked while the rest review the normal one, keeping the round an A/B. The argument, from a reviewer that raised it and no other: this codebase's comments are unusually strong, which is exactly why a wrong one is persuasive — the ceiling that turned out 4x too tight came with a confident account of its own derivation, and every reviewer that read it inherited that premise before forming its own. A bare number invites *"where did this come from?"*; an explained number suppresses the question. Measured on a real 445 KB bundle of this repo, **43% of it was commentary**. Line numbers are preserved deliberately: deleting comment lines would shift everything after them and era validates `file:line` citations against the bundle, so a stripped seat would have all of its citations flagged as fabricated. repomix's own `--remove-comments` cannot do this job here — checked against 1.12.0, it covers 33 extensions and `.ps1` is not one of them. **Measured 2026-09-01, then replicated and NOT reproduced (v2.8):** two within-model A/B pairs at n=1 showed the blinded arm producing more premise findings than the same model sighted (1 vs 0, and 3 vs 1). Sixteen more cells across **two subjects**, plus a blinded third-party re-score of the original four, leave the difference at **exactly zero** on the one model measured at n=4 in both arms (4.50 vs 4.50, within-cell spread 0–7); the second subject moves **both** pairs the other way (−1 and −5); and the re-score changed three of the four original counts (1→5, 3→6, 1→4), so the two scorers disagreed by more than the effect. Five within-model pairs now exist: two positive, two negative, one flat. The feature rests on its argument; the measurement does not support it, and the docs no longer say it does. The same run showed the cost: a sighted seat found a defect discoverable *only* because a comment stated the intent the code violated, which is why exactly one seat is blinded. Method and full scoring in `docs/assessments/2026-09-01-blind-seat-ab.md`.

- **A locked directory no longer kills the round silently-wrongly (v2.4)** — repomix aborts the *entire* run on one unreadable directory, and the usual culprit is a live browser profile (`PermissionError: Permission denied while scanning directory`). A `.repomixignore` in the reviewed repo **cannot** prevent it: repomix hands that file to globby as an `ignoreFile`, so globby walks the locked directory while globbing for the file that would have excluded it — only the ignore-pattern list prunes traversal, and narrowing `-IncludeFiles` does not help because the full-tree walk happens regardless. Browser-profile directories are now pruned by default (also a privacy control — a live profile holds session cookies, and era uploads the bundle to a third party), and the abort now explains the cause, the fix, and explicitly what is *not* the fix.
- **Fabricated `file:line` citations are flagged (v2.4)** — one model was measured citing lines 5891, 5360 and 3612 of a 2,834-line file across two separate rounds. era reads each bundled file's line count and checks every citation against it, reporting any that point past the end of the file. Advisory by design: the prose findings were often correct and twice genuinely novel, so it is the line numbers that are untrustworthy, not the reasoning. Basenames that appear at more than one path are skipped rather than guessed — an over-eager checker that cries wolf on a correct citation is worse than none. **It also has to be able to SEE the citation (fixed 2026-09-02).** The matcher accepted `path:207` and not `path:L207`; 138 citations in the 108-response archive are in that anchor form and every one is from an `agy` seat — the `disk-read` path, whose own reader produces the bundle-absolute numbers this checker exists to sort out, so it was blindest exactly where it mattered. Seven responses scored `Checked=0`, which era prints identically to a clean review. With `:L?` accepted, `gemini` goes 190 → 248 citations checked and 11 → 28 flagged, **28 of 28** of them the coordinate frame, and no seat gains a single new non-frame flag — so the v2.8.2 archive figures undercounted the **`gemini` seat's** *flagged* citations by ~61% (11 of the 28 that exist) and its *checked* citations by ~23% — both agy seats together, 27 of 50, is ~46% — through era's own regex rather than through the models. (The first write-up of this said "the agy seats" where the 61% was one of them; caught by the opus seat of the panel on it.)
- **A non-review says which kind it was (v2.4)** — `agentic-narration-capture` covered three faults needing three different responses and named only one of them. The summary now reports `bundle-access-refusal` (the model could not see the bundle — look at delivery, not the prompt), `sub-floor-non-answer` (it answered, briefly and without structure — **often not narration at all**; a correct 280-character answer was rejected while 301- and 324-character ones passed), or `tool-intent-narration`. The error *code* is unchanged so the bounded fallback re-dispatch still triggers.

- **Every reviewer's delivery channel is checked before dispatch (v2.3)** — each backend gets the bundle a different way, and each way has a different ceiling: `opencode` **attaches** (silent truncation at 51,200 bytes) or **reads from disk** (verified to 668,389); `claude` **inlines via stdin** (measured ~600k tokens); `agy` **reads from disk** (unbounded); the REST adapters put it in a request body. Nothing checked any of that. Three consecutive 4-seat panels delivered 2 seats — a 2,396,233-byte bundle came back `Prompt is too long` from `opus`, and both opencode seats timed out at 600 s having returned nothing. The only pre-existing scale gate measured *pre-bundle source* bytes against a 10 MB ceiling — ~200x looser than the tightest channel era dispatches to — and armed only when no `-IncludeFiles` was passed, so all three curated rounds sailed through it. era now measures the bundle it actually built against every selected seat and **refuses with exit 1** (nothing dispatched, nothing spent, free to re-run) when a seat cannot possibly succeed; `-ForceBundleSize` / `ERA_BUNDLE_FORCE=1` dispatches anyway with a per-seat warning. The round summary names each seat's **delivery mode** (`via=attach`, `via=read-tool`, `via=stdin`, `via=disk-read`) and its **failure category** — `not-delivered` (nothing was reviewed; the seat's silence carries no information) as against `answered-badly` (the bundle *was* reviewed and the answer was rejected). `round-N-metadata.json` records `delivery_mode` per reviewer and `bundle_bytes`. Limits live in `backends/_registry.json` as `max_bundle_bytes` / `max_bundle_tokens`, so a newly measured ceiling is data, not a code change (this wiring was dead in v2.3 while being documented as working — fixed in v2.3.1 with an end-to-end test). Full method and numbers in `docs/assessments/2026-08-31-bundle-delivery-limits.md`.
- **The stall forensics were empty for the wrong reason (v2.3)** — every artifact under `%TEMP%\opencode-stall-debug` was 0 bytes while the error line beside it reported a non-zero `total bytes`. That contradiction read as "the process produced nothing" and sent a diagnosis after a startup failure that was never happening. `FileStream.Length` counts bytes still sitting in the write buffer, and the snapshot copied the file **without flushing**. Reproduced exactly: 218 bytes in → `Length` 218, on-disk 0, after `Flush()` → 218 — the same 218 as the log. Every artifact recorded before this fix is empty or cut at a 4,096-byte boundary for that reason, not because the backend was silent. ⚠️ A broken measuring instrument is worse than no instrument: it was briefly used to justify retiring a delivery path that works (below).
- **Bundles over 50 KiB reach opencode (v2.3)** — above the attach cap the model is told to read the bundle itself. That path was retired and un-retired the same day; the case for retiring it rested entirely on the empty artifacts above. Measured properly with **canaries** — marker lines planted at widely separated depths and asked back verbatim *before* the review, because a review coming back does not prove coverage — both default opencode seats returned markers from 25/50/75% depth on **109,066 B (57 s), 314,720 B (85 s) and 668,389 B (256 s)** bundles — 13x the attach cap. ⚠️ A returned marker proves **retrievability**, not that the model read the content in between; what supports the stronger claim is the conjunction of markers, grounded `file:line` citations across a 10,773-line bundle, and wall-clock scaling with size. It remains **intermittent in a way that is not explained** (the same seat lost rounds at 74,740 and 79,294 bytes, sizes these probes clear comfortably — neither size nor model). Concurrency was the leading hypothesis and **has since been tested and ruled out (v2.3.2)**: 10 trials with an `opencode serve` holding the database plus 22 external `opencode run` contenders produced **0 stalls**, identically to 10 trials with no other opencode process, and `database is locked` never appeared. The cause is genuinely unknown, with concurrency now the least-supported explanation. Caveat: those trials finish in ~13 s while the historical failures burned 600 s, so the failing regime was not reproduced.
