# Tests

Pester 5 unit tests covering the high-risk surface of `/era`. Run before merging anything that touches `backends/`, `workflow.ps1`, or `runtimes/era.ps1`.

## Prerequisites

```powershell
Install-Module Pester -MinimumVersion 5.0 -Force -SkipPublisherCheck
```

## Running

```powershell
# All tests
pwsh -Command "Invoke-Pester -Path tests/"

# One test file
pwsh -Command "Invoke-Pester -Path tests/Get-AgyTranscriptResponse.Tests.ps1"

# Verbose output (see every It block as it runs)
pwsh -Command "Invoke-Pester -Path tests/ -Output Detailed"
```

Tests are pure PowerShell and, **as of 2026-09-04, spawn no live backend** — that claim was false until then and is worth reading as a caution about documentation drift. `BroadScopeGate.Tests.ps1` and `AutoDetect.Tests.ps1` fork a real `era.ps1` to exercise behaviour that happens *before* dispatch, and several of those forks passed neither `-IncludeFiles` nor `-Reviewer`, so era correctly dispatched the **full default panel**. A suite run therefore spent money on real models, and — because both opencode seats serialise on `Global\era-opencode-run-mutex` — a suite BLOCKED a concurrent live round for 476 s (era's own log reported it: `476s already spent waiting for the run lock`). It also explains why `BroadScopeGate` was the second-slowest file at 216.78 s. Those forks now set `ERA_PREFLIGHT_ONLY=1`, which runs every gate and stops before dispatch. Tests are otherwise pure PowerShell with no network (1,112 tests as of 2026-09-04, up from 1,096 the same day, 1,031 at v2.8.1 and 961 at v2.7.1). ⚠️ `BundleDeliveryWiring.Tests.ps1` copies the whole skill tree and forks a real `era.ps1` per case, which is why it is the slowest file by a wide margin — it exists because the unit test it replaced passed while the feature was dead, so the cost is deliberate. Budget for it when running the full suite. **The obvious optimisation was tried and does not pay:** sharing one skill-tree copy across the cases (keeping the per-case fork) measured 84.0s ± 18.5 against 80.3s ± 15.6 for the per-case sandbox, n=3 each, alternating — no effect, on a difference smaller than a third of the run-to-run noise. The tree copy is not the cost; the six `era.ps1` forks are, and those are the part that must not be traded away. It was reverted rather than kept, because it also couples the cases through one mutable sandbox in the file whose isolation is the point. Most are fast; a few (`Resolve`, `SpecReview`, `Invoke-Era`, `AutoDetect`) fork `pwsh` to exercise `era.ps1`/`resolve.ps1` end-to-end, so a full run with `-ExcludeTagFilter Slow` is **~6 min** measured 2026-09-01 (the ~20 min figure this line used to carry was never re-measured after the Slow tag was introduced) (one `Slow`-tagged ThreadJob test alone takes ~30s; exclude it with `-ExcludeTagFilter Slow`). No external dependencies.

| `BlindSeat.Tests.ps1` | The comment-stripped seat. Also: whole-line comments blanked across PowerShell/Python/JS, block bodies blanked without a one-line block swallowing the code after it, code left alone, a Markdown `#` heading NOT treated as a comment, and a trailing comment left in place as documented. Plus the wiring — one seat gets the alternate bundle and the others do not, the stripped copy is built after repomix from the finished bundle, and naming an undispatched seat warns rather than silently doing nothing. |
| `FieldReports20260901.Tests.ps1` | Three issues from a field report: the browser-profile ignore patterns (present, and spelled with the load-bearing `**/` prefix that stops them being root-anchored) plus the permission-abort message that says what is *not* the fix; citation grounding against a synthetic 2,834-line bundle reproducing the reported fabrications, including the refusal to guess on an ambiguous basename and the "findings may still be real" wording; and the non-review branch split — a short bundle refusal must be named a refusal rather than sub-floor, the error *code* must stay `agentic-narration-capture` so recovery still triggers, and no branch may leak from a previous call. | `BundleDeliveryWiring.Tests.ps1` | **End-to-end** wiring for the delivery gate, written because the unit test above it passed while the feature was dead. Copies the skill tree to a temp dir, edits the copied `_registry.json`, runs the real `era.ps1` against a real git repo, and asserts on what era prints — `max_bundle_bytes` / `max_bundle_tokens` honoured, `0` treated as a real ceiling rather than as absent, a non-numeric value warned about and ignored, and exit **1** with nothing dispatched. Free and hermetic: an over-ceiling bundle is refused at preflight before any reviewer runs. Verified by negative control — with the two projection lines removed it prints the built-in ceiling and dispatches. |
| `BundleDeliveryPreflight.Tests.ps1` | Each seat's delivery channel vs. the bundle era actually built. `Get-EraBackendDelivery` (opencode `attach` under 51,200 bytes / `read-tool` above it, `claude` by tokens, `agy` unbounded, unmeasured providers never refused) and `Get-EraBundleDeliveryPlan` driven with the REAL sizes from the rounds that failed — 74,740 / 109,066 / 314,720 / 668,389 / 2,396,233 bytes and repomix's own 711,253-token count — plus the `era.ps1` wiring: the plan runs before the cost prompt, refuses with exit 1, and gates its override behind `-ForceBundleSize` rather than `-Force`. Pins the measured `claude` ceiling inside its bisected bracket, so neither a regression to the old derived 150,000 nor a rise above the measured accept point passes. |
| `OpencodeReadToolDelivery.Tests.ps1` | The over-the-cap Read-tool path, and the snapshot bug that once hid how it behaves. Includes a **live .NET repro** of that bug — 218 bytes copied into a `FileStream` gives `Length` 218 and an on-disk length of 0 until `Flush()` — because it is the reason six stall artifacts read as "the process produced nothing" and the reason the path was briefly retired. Asserts the snapshot flushes *before* it reads, that size alone routes to the Read tool, that the refusal only fires past the verified 1,048,576-byte ceiling and costs a second rather than a timeout, and that the source records the canary measurements **and** the unexplained intermittency — a comment reporting only the passes is arguing for its conclusion. |
| `VoidRound.Tests.ps1` | A round that produced no usable review must not report success. `content_ok` and `Test-EraReviewerArtifact` are grounded in the response artifact on disk, not in the adapter's `ContentOk` flag (which agy sets `$true` even when its process was killed) and not in a clean exit code (which for REST backends only means the HTTP call worked); `Get-EraVoidRoundReport` plus the `era.ps1` gate that exits **2** — distinct from the preflight exit 1 — when nothing readable was produced. |
| `AdapterTimeBudget.Tests.ps1` | `Resolve-OpencodeRunBudget` — every wait inside the opencode adapter comes OUT of the dispatcher's `TimeoutSec`, never gets added to it. The twin of the v1.x stall-escalation fix, reintroduced by the run mutex that landed after it: a fixed 900s lock wait against a 600s default budget, a `$deadline` stopwatch started *after* that wait (so the adapter's own timeout was `lockWait + TimeoutSec`), and a `database is locked` retry that recursed with the unchanged budget. Sweeps five budgets x seven elapsed values asserting the ordering holds, and composes with `Resolve-OpencodeStallPlan` to show the stall still fires first after a long queue. **The sweep asserted nothing for two releases**: `LockWaitMs/1000 -le RemainingSec` and `RemainingSec - LockWaitMs/1000 -ge 0` are the same inequality written twice, and against a decoy whose lock wait consumes the entire remaining budget the pair passed 35 of 35 pairs. It now asserts the FLOOR (`remaining - lockWait >= Min(MinRunSec, remaining)`), which fails 23 of those 35. |
| `OpencodeHintAmbiguity.Tests.ps1` | The **third** implementation of "an ambiguous model hint must not be resolved silently". v2.4.1 fixed the agy branch, v2.7.1 fixed era.ps1's copy; the opencode branch of `Resolve-ModelFromHint` was still first-match-wins over `_registry.json` file order. Not a hashtable, so it never varied run-to-run — which is why two `.Keys` sweeps walked past it. The red test builds the same entries in two insertion orders and asserts the same model comes back; measured, `deepseek` returned `deepseek-v4-**pro**` from one ordering and `-flash` from the other. |
| `FallbackBundleOverride.Tests.ps1` | `Get-EraSeatBundle` / `Get-EraFallbackBundleOverrides` — the `-BlindSeat` fallback fix that fixed nothing. v2.7 threaded `-BundleOverrides` into the fallback re-dispatch; the map is keyed by preset and `Resolve-EraAgyFallback -Exclude` guarantees the fallback's preset is absent from it, so the lookup could never hit and the blinded seat's replacement still read the sighted bundle. It shipped with a source-assertion test that the parameter *exists*. Now the override is re-keyed onto the preset the fallback actually dispatches under, and either outcome is printed. |
| `OpencodeConstantParity.Tests.ps1` | The file `backends/opencode.ps1` has claimed in a comment since 2026-08-31 "pins the built-in values against the plan's". It did not exist — the real guard lived in `BundleDeliveryPreflight.Tests.ps1` and scraped the adapter's source with a regex. Both sides are now *called*: attach cap, read-tool ceiling, the mode crossover at the boundary byte, and the rule that a registry override moves the read-tool ceiling and not the transport's own truncation point. Also covers `Get-OpencodeBundleBytes` failing CLOSED — the old `catch { 0 }` made an unreadable bundle look small enough to attach, which is silent truncation reached through a fail-open. **A second pair, in the time dimension:** `MinRunSec` is documented as "one 10s poll of the output loop plus margin" and was derived from a `$pollMs = 10000` literal ~500 lines away by that comment and by nothing else. Both now come from `Get-OpencodePollIntervalMs`, and the rule (the floor covers at least one poll, with margin, at every budget, and the viability boundary sits on the same number) is asserted here. Measured with the decoupling restored (poll 30000, `MinRunSec` default back to the literal 15): 3 of the 32 assertions across this file and `AdapterTimeBudget.Tests.ps1` fail, and all 3 are new. Before this change, none would have. |
| `BlindSeatRecord.Tests.ps1` | Which seat was blinded is recorded in `round-N-metadata.json` (`blind_seat`, per-reviewer `blinded` and `delivery_bundle`). Found while replicating the A/B: the arm label of the experiment existed only in a console line and in the prose of the assessment that scored it. Same shape as the citation warnings, which were console-only until they were recorded. |
| `PerReviewerCapParity.Tests.ps1` | The per-reviewer cost cap exists twice: `Get-PerReviewerCap` in the plan, and an inlined copy in `backends/agy.ps1` that gates its in-adapter retry. The duplication cannot be removed (the adapter dot-sources only itself) so the drift is what gets tested — both sides are called across the pricing range and at the `input_per_m >= 10` boundary. The dangerous direction is the adapter's cap drifting *high*: it would re-spawn a reviewer the plan refused to pay for, after the cost prompt was already answered. Also pins `Get-AgyBundleBytes` failing CLOSED — the old `else { 0 }` made an unreadable bundle cost zero estimated tokens, which disarmed the cap entirely. |
| `AgyTieBreakParity.Tests.ps1` | Two agy resolvers, both made deterministic by separate releases, tie-breaking on **different keys** — `resolve-model.ps1` on `settings_value`, `era.ps1` on `display`. Sort-Object is stable, so a `TierRank` tie could name a different model depending on which resolver asked. Measured against the shipped registry they do **not** currently diverge, so this is latent, not live; the sweep over every ambiguous hint is what makes the next registry entry fail the suite instead of shipping. Raised by the blinded seat of the twin-sweep panel. |
| `AgyHintResolverFourth.Tests.ps1` | The **fourth** copy of the ambiguous-hint rule, and the only one that never worked. `Find-AgyModelFromHint` named its accumulator `$matches` — an automatic variable that PowerShell overwrites on every `-match`, which is the loop's own condition — so the list became a hashtable holding the LAST match plus regex group 0, `.Count` counted keys, and the tier sort had one object to sort. Measured over five separate processes, hint `gemini` gave three different models. **In-process repetition cannot see this**: a hashtable's enumeration order is fixed for one process's lifetime, so the test forks. Raised by the opus seat of the panel run on the sweep that had just declared this rule closed. |
| `AgyPromptHonesty.Tests.ps1` | **The prompt and the delivery classification must describe the same world.** `Get-EraBackendDelivery` calls agy `disk-read` — the string that reaches every round's `delivery_mode` and is why this seat has no size ceiling — while `backends/agy.ps1` told the model *"Do NOT open, read, fetch, list, or run anything"*. Opus raised the contradiction (F12) and it sat open for two releases. Resolved by experiment: a 418-byte bundle whose only content was a random sentinel absent from the prompt came back as `SENTINEL=ZQ7X-39CEB86379E6` with `HOW=... viewing sentinel-bundle.xml on disk using the view_file tool`. The classification was right; the prompt was the lie the seat had to disobey to work at all. These tests pin both ends against `Get-AgyReviewPrompt` (called, not grepped — the adapter's docstring now quotes the OLD prompt in full, so any source grep for it passes on a comment), including that every ban on opening or reading carries an exception for the one file the seat must read. |

| `CitationCoordinateFrame.Tests.ps1` | `Get-EraBundleFileSpans` and the two coordinate systems a `file:line` citation can be written in. A repomix bundle prints each file's OWN line numbers; a **read-tool** seat opens that bundle with its own Read tool, which reports **bundle-absolute** ones. era knew only the first, so it reported the second as fabrication — measured across 62 archived seat-responses (25 rounds), **128 of 155 citations past end-of-file (83%) land inside the named file's span in the bundle**, out of 1,570 checked. The checker now separates the frames and translates, and the tests pin the translation (`bundle B in a span starting at S is in-file B − S`), the back-compat path with no spans supplied, that a genuine fabrication is still caught, and — the load-bearing one — **the blind spot**: where the two frames overlap (203 of 1,570 citations, 12.9%) nothing can tell them apart, so 83% is a rate over the *flagged* set and not over frame errors. Runs against a committed fixture reproducing a real round's exact 12-file geometry, not against gitignored artifacts. |

| `RoundClaimRetryScope.Tests.ps1` | **`catch [System.IO.IOException]` is not "the claim file already exists".** `Reserve-ReviewRound` claims a round number with `File::Open(..., CreateNew, ...)` and retries on `IOException`; four subclasses of that do not mean contention, and the loop spun 50 times on them before throwing a message about an inconsistent directory. It has already cost a release (`f33705a`: era could not claim a round at all on a UNC path, because `DirectoryNotFoundException` derives from `IOException`) — **the path bug was fixed there and the catch was not**. Classified by execution, not by reading: real `File::Open` calls against the real filesystem show a collision arriving as a bare `IOException` while a missing parent, a non-existent drive and an over-length path all arrive as `DirectoryNotFoundException`. The catch clauses themselves are read from the **AST** — a grep would pass on a type name in a comment or in another function — including that the narrow clause is ordered *before* the wide one, since PowerShell takes the first matching clause and a base type matches its derived ones. |

## What's NOT covered

- **Live backend dispatches** — running agy/claude/opencode would require live auth, real network, and minutes of wall clock. Use the manual smoke-test pattern (small bundle + `--reviewer <preset>`) for those.
- **`era.ps1` argument parsing** — covered implicitly by smoke tests; would benefit from a future test file if argument logic grows.

## When to add tests

- Adding a new backend → extend `Registry.Tests.ps1` + add to `EnvScrub.Tests.ps1` if CLI.
- Touching `Get-AgyTranscriptResponse` → run the existing tests and add one for the new behavior.
- Changing a regex anywhere → add cases to `Regex.Tests.ps1`.
- Bug fix → add a regression test in the file closest to the fix's concern.
